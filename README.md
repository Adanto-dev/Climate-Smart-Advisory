# Climate-Smart Advisory

An agent that turns rainfall, pest and price signals into **sourced, household-level planting / spraying / holding advice drafts** for an agricultural extension office. **The agent drafts. A named officer decides.** Nothing is sent to a farmer, ordered, or flagged for credit until a human approves it by name.

Built for the Qhala *African Agentic AI Design Challenge* — Agriculture track, theme **Climate-smart advisory**. Licence: MIT.

> **Read this first (honest status).** All data is **synthetic**. No extension officer or farmer has reviewed the rules. The open-weights (`--backend llm`) path is implemented and its plumbing is tested against a *mock* model, but **it has not yet been run against a real open-weights model** (the build sandbox had no model host or GPU). See [What is unfinished](#what-is-unfinished).

## Run it (one command)

Needs Python 3.11+ and internet for the first `pip install`.

```bash
git clone <this-repo> && cd climate-smart-advisory && ./run.sh
```

`./run.sh` creates a venv, installs, generates the synthetic data, runs the agent over 3 collectives (12 households), then **stops at the officer gate** and asks you for your full name and approve / reject / edit per item.

```bash
./run.sh --yes-as "Grace Wanjiku"   # non-interactive; approval is SIMULATED and logged as mode=simulated
./run.sh --detach                   # stop at the gate, review later with `python -m csa.cli review --run <id>`
./run.sh evals                      # re-run 17 eval cases, regenerate EVALS.md
./run.sh test                       # unit tests
python -m csa.cli audit verify      # check the hash chain of runs/audit.jsonl
```

## Open-weights run (data stays in-country)

```bash
ollama pull qwen2.5:7b-instruct            # or any tool-calling model served OpenAI-compatibly (vLLM, llama.cpp)
./run.sh --backend llm                     # defaults: CSA_LLM_BASE_URL=http://localhost:11434/v1  CSA_LLM_MODEL=qwen2.5:7b-instruct
CSA_LLM_BASE_URL=... CSA_LLM_MODEL=... CSA_LLM_API_KEY=... ./run.sh --backend llm   # a frontier model alongside, for comparison
```
Token counts, tool-call counts and elapsed time are written to the `run_summary` audit entry (cost per run). The `rules` backend (default) uses no model at all and exists so a stranger can run everything offline.

## How it works

```
start ──► work ──► verify ──► approval_gate ──► dispatch ──► END
  │         ▲          │            │ interrupt(): graph pauses for a human
  │         └─ retry ──┘            ▼
  │         (llm backend,      named officer approves / rejects / edits each item
  │          max 2)
  └─ MCP: csa-extension (built) + mcp-server-time (borrowed)
```
- **work** – per household: read plot → fetch rainfall / pest / price signals → draft. `rules` backend = deterministic planner ([`csa/policy.py`](csa/policy.py)); `llm` backend = tool-calling loop with the same rules as a prompt.
- **verify** – an *independent* self-check: re-fetches evidence with read tools and withdraws any draft the evidence does not support (e.g. PLANT without onset, SPRAY without a fresh alert).
- **gate** – LangGraph `interrupt()`. Approval needs a human full name; rejections are always allowed.
- **dispatch** – [`csa/dispatcher.py`](csa/dispatcher.py), not reachable through MCP. Re-checks the approver and a SHA-256 of the exact content that was approved; edits after approval are refused.

### MCP servers

| Server | Built / borrowed | Tools |
|---|---|---|
| `csa-extension` ([`csa/mcp_server.py`](csa/mcp_server.py)) | **Built** | read: `list_households`, `get_household_plot`, `get_rainfall_signal`, `get_pest_alerts`, `get_market_prices` · write (draft-only): `draft_advisory`, `file_flag`, `schedule_followup` |
| [`mcp-server-time`](https://github.com/modelcontextprotocol/servers/tree/main/src/time) | **Borrowed** (official reference server) | `get_current_time`, `convert_time` |

*Why borrowed beats written:* timezone/DST handling is easy to get subtly wrong, and the official server already does it; we use it to stamp when an advisory was issued (Africa/Nairobi).

Write tools only create `PENDING_APPROVAL` rows. There is **no** tool that sends, orders or files credit; `draft_advisory` / `file_flag` / `schedule_followup` reject any citation id that no read tool returned in this session, so the model cannot invent a source.

### Audit log
Every tool call (inputs, outputs, error, ms), plan, self-check, officer edit, approval (officer name, mode, content hash), refusal and dispatch is appended to `runs/audit.jsonl`, hash-chained so edits are detectable (`audit verify`).

## Data
Synthetic, generated by [`scripts/make_data.py`](scripts/make_data.py), pinned to 2026-10-07 (`CSA_AS_OF` overrides). Shapes imitate CHIRPS-style dekadal rainfall, a seasonal outlook, WhatsApp-style pest alerts and weekly market prices. Deliberately messy: mixed units (ha/acres), missing plot size, a missing rainfall dekad, a station with no data, a stale pest alert, a price entry error, a duplicate household, a household with no phone, yields recorded in bags. **Not covered:** real soils, real crop calendars per zone, real extension messaging rules, USSD session handling, local languages.

## What is unfinished
- **No real open-weights run yet** (see top). Mock-model results only prove plumbing.
- **Not validated with an extension officer or farmers.** Thresholds (≥40 mm over two dekads for onset; ±5% price trend for hold) are illustrative.
- **Known failing eval E17:** planting date is never cross-checked against onset ([EVALS.md](EVALS.md)).
- The SMS / USSD / order / credit "gateways" are stubs that append to `runs/outbox/*.jsonl`.
- Approval state lives in SQLite on one machine; there are no officer accounts or auth — the officer's name is typed, which is an honest-process control, not identity assurance.
